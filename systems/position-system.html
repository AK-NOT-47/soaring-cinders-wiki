Combat Position System

CANONCross-IterationMixed
Also known as: 2x3 grid, Vanguard/Sentinel grid, Formation system, Rank line
First conceived 2023-02-02 (M00859, CrunchyConniptions) · last in chat 2023-12-20 (M05169)

Combat Position System CANON

Where each combatant stands governs what they can hit, what can hit them, and how skills behave — the tactical spine of turn-based combat.

Summary — The finalized design is a 2×3 grid (2 rows × 3 columns = 6 spaces): the front row are Vanguards (orange), the back row are Sentinels (yellow), built with 4 active characters in mind (008 §8 Combat Position System v2.0; M05108, FreshToast; M05149, CrunchyConniptions, 2023-12-20). Movement is simple and perfectly deterministic — never random, generally one step. This grid explicitly replaced the earlier Darkest-Dungeon-style row line, which the team judged “an inferior imitation” (M05124, CrunchyConniptions, 2023-12-20). The playable proto ships a simplified vertical-slice version — a single-axis rank line (heroes ranks 1–4, enemies ranks 1–3, rank 1 = front) — not the grid; the grid remains the documented design target (008 §8, DEBATED design intent vs implemented).

Description — the 2×3 grid (design target, notes-design)

  • Grid: 2 rows × 3 columns = 6 spaces, built for 4 active characters (it could occasionally flex — events with only 2, or jumping in a 5th NPC) (008 §8; M05108, FreshToast, 2023-12-20).
  • Rows / roles: Front row = Vanguard, which must be orange; back row = Sentinels, which must be yellow (000 lines 8135–8136; M05149, CrunchyConniptions, 2023-12-20). The names Vanguard/Sentinel were liked on sight (M05147, CrunchyConniptions, 2023-12-20).
  • Why 6: Largely arbitrary but deliberate — as few spaces as possible to avoid becoming a “bad XCOM”; 2 deep (not 1) for easy lateral movement; 6 is visually pleasing over 5s/7s/11s (008 §8; answering M05124’s “why 6?”).
  • Movement: Perfectly deterministic — never random, generally one step, no contradiction-chains (“if that would result in weird movement or some contradiction, then no moving happens”). You always know where a shoved character goes. Inspired lightly by XCOM and D&D (M05104, FreshToast, 2023-12-20); comparisons to Into the Breach, Etrian Odyssey, Fire Emblem, Yu-Gi-Oh (008 §8).
  • Targeting: Most actions can hit someone in front or in back (some hit either). Area actions hit all 3 spaces in a set, or 2 in a lane (top/middle/bottom straight line — e.g. a big thrust). Many actions also care about where the actor stands (008 §8).
  • Tactics, not just targeting: “The point of the position system is not just a matter of targeting, enemies change tactics and become more/less effective based on position as well” (M02538, FreshToast, 2023-02-20).

CANON AoE vs multi-position enemy bonus

An AoE that hits an enemy which occupies multiple positions deals bonus damage — “as if hit twice but not double damage, maybe an extra 20%.” This is load-bearing for the Vaenngrym climax, where he fills all 4 positions (000 lines 3141–3142; M01842, FreshToast, 2023-02-13).

Rules — the shipped rank line (proto-implemented)

CANON · implemented The proto does not ship the 2×3 grid. It implements a single-axis rank line: rank 1 = front (closest to the opposing side), higher numbers = further back; heroes have up to 4 ranks, enemies up to 3 (008 §2 Battle Mechanics; proto src/core/combat/types.ts Position = 1|2|3|4). The GameBible and GAME_DESIGN.md §5.3 frame this same shipped system as the Front / Mid / Back band model.

  • Rank governs which ranks an actor can act from (fromRanks) and which ranks a skill can target (targetRanks) (008 §2).
  • Shoves are deterministic single steps via the move skill effect (008 §8).
  • On a defeat, survivors compact forward to close the gap (008 §2; proto compactPositions). This forward-compaction replaces the scrapped corpse system and the Remnant trace, neither of which is coded.
  • Ambush scatters the party’s starting ranks: an ambush node flag triggers a Fisher–Yates shuffle of hero ranks before the fight builds (008 §2 Encounter & Initiative; M?—see 008).

Related systems

  • Turn order is driven by Speed/Initiative, not position — the implemented rank line has no position-based turn order and no movement cost (008 §8 Formation Mechanics note). See Action Points (AP) Economy for the action budget spent to move and act.
  • Rank-Targeting / Combat-Readability UI — the PROPOSED UI that telegraphs a skill’s own from-rank/target-rank.
  • Formations, pairing, and position-based team skills are DEBATED design layered on the grid (008 §8 Party/Team Skills); not implemented.
  • Locke’s leadership is designed to be expressed through formation mechanics — “she is glue that brings them together” (008 §18).

Open questions

  • DEBATED The 2×3 grid vs the shipped single-axis rank line: the grid is the documented design target; the rank line is the vertical-slice implementation (008 §8, DEBATED design intent vs implemented).
  • SCRAPPED for first game A 3×2 variant (adding a centre 3rd column) was considered — “just complicated… didn’t fix some of my gripes with DD but I liked how it looked” (M05141, FreshToast, 2023-12-20) — left open only as possible post-first-game experimentation.
  • SCRAPPED Behind-area / pincer combat (an area behind both sides, surrounding/assassin play) was rejected as “a step too far in terms of scope”; recorded as a Finalized Design Decision: “No behind-area combat mechanics (too much scope)” (008 §2 Behind-Area/Pincer, Part 23).

Design history

  • 2023-02-02 — original concept: a battle map with a positioning line, “Back Back / Front front,” Darkest Dungeon & Radiant Historia style (M00859, M00851, CrunchyConniptions; “Back Back / Front front” is M00860, FreshToast). (Ledger R05.)
  • 2023-02-07 — DD-style refinement: a line of 4 positions per side, blue = character / orange = enemy, back rank = back 2, front rank = front 2 (reversed for enemies), simplified pips (M01084, M01093–M01098, FreshToast, 2023-02-07).
  • 2023-02-09 onward — the frontliner/backliner DD-style role system (Part 9) carried the Vanguard-vs-Sentinel role philosophy forward but kept literal DD rows.
  • 2023-12-20 — the Combat Position System v2.0 (2×3 grid) was adopted to explicitly replace the prior DD-style row system: “our previous version was essentially an inferior imitation of Darkest Dungeon… Addressing this was crucial” (M05124, CrunchyConniptions). Front row = Vanguard (orange), back row = Sentinels (yellow), stated as “sentinals must be yellow and vanguards orange” (M05149, CrunchyConniptions, 2023-12-20) — supersedes the DD line. The grid also removed the need for a corpse system and forced 4v4s. (This is the current design presentation above.)
  • Color-swap correction: the raw phrasing lists the back role first — “sentinals must be yellow and vanguards orange” (M05149) — so a reader following word-order could wrongly map front→yellow / back→orange. The canonical mapping per the 000 notes is unambiguous: Front = Vanguard = orange; Back = Sentinels = yellow (000 lines 8135–8136). Do not swap them.
  • Later (proto era) — the playable proto ships a simplified single-axis rank line (heroes 1–4, enemies 1–3) as a vertical-slice stand-in; the 2×3 grid remains the design target (008 §2/§8, DEBATED design intent vs implemented).
