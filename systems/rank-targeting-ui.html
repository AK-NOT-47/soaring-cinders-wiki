Rank-Targeting / Combat-Readability UI

PROPOSEDCross-IterationNotes / Design
Also known as: Rank indicators, targeting UI, combat readability UI
First conceived 2023-02-06 (M01030, FreshToast) · last in chat 2023-02-06 (M01047)

Rank-Targeting / Combat-Readability UI PROPOSED

Player-side visual feedback for how a skill’s rank/target range works and what the player has selected — distinct from the enemy-side intent telegraphs.

Summary — PROPOSED A player-facing readability layer for the rank/position system: colored indicators show which rank a skill can be used from (yellow) and which it can target (blue), potential targets are highlighted (with an AoE link), selection is made obvious via glow/halo, and enemy health that would be deleted is previewed Darkest-Dungeon-style (008 §7 Rank-Targeting UI; M01030–M01047, FreshToast/CrunchyConniptions, 2023-02-06). This is player-side targeting feedback — distinct from and complementary to the Enemy Intent Indicators; the two should not be duplicated. All conceived in a single 2023-02-06 readability thread; not implemented.

Description PROPOSED

(008 §7 Rank-Targeting / Combat-Readability UI; all from the M01030–M01047 thread, FreshToast/CrunchyConniptions, 2023-02-06)

  • Rank indicators on a skill: a yellow indicator shows which rank a skill can be used from; a blue indicator shows which rank it can target. Left arrow = left rank (back for party, front for enemy); right is the opposite. Framed as more immediately intuitive than text like “Skill only usable from back rank” (M01030, M01031, M01032, M01035, FreshToast).
  • Iteration / simplification: the blue symbol could be dropped so only the yellow appears (M01034, FreshToast).
  • Target highlighting: instead of a target symbol, highlight the enemies that are potential targets, with a visual link between them for AoE effects. Visual reminders sit underneath enemies; Darkest Dungeon does something similar with its “4 dots” (M01033, M01036, M01037, FreshToast).
  • Selection feedback: when a character is selected it should be more obvious — a drop-shadow glow under the character, a halo, or a low-effort eye-catching arrow; the health bar could change color or glow (from the same thread).
  • Enemy health preview (Darkest-Dungeon style): highlight the portion of an enemy’s health bar that would be deleted by the selected action (“the enemy themselves are highlighted and the portion of their [health] that would be deleted is highlighted” — noted as harder to implement). Otherwise show enemy health as numbers in the lower UI (M01042, M01043, M01044, M01047, FreshToast/CrunchyConniptions).

Related systems

  • Reads directly off the rank/position system — the yellow/blue arrows visualize a skill’s fromRanks/targetRanks.
  • Distinct from Enemy Intent Indicator System: that telegraphs what the enemy is about to do; this shows the player’s own skill range and selection. Complementary, not duplicative (008 §7 note).
  • Color note: the same 000 UI thread uses blue for a character’s position, orange for an enemy’s position on the combat map (000 line 1852) — separate from the yellow/blue skill-range indicators here.

Open questions

  • PROPOSED Whether to keep both the yellow (used-from) and blue (target) indicators, or drop the blue so only yellow appears (M01034, FreshToast, 2023-02-06).
  • PROPOSED The DD-style health-deletion preview is the preferred option but noted as “more difficult to implement” (M01042, CrunchyConniptions, 2023-02-06).
  • Whole system is PROPOSED / notes-design — not implemented in the proto.

Design history

  • 2023-02-06 — the entire proposal was worked out in a single combat-readability thread: yellow = used-from-rank / blue = target-rank arrows, the option to drop blue, potential-target highlighting with AoE links, selection glow/halo feedback, and the DD-style enemy-health-deletion preview with numbers in the lower UI (M01030–M01047, FreshToast/CrunchyConniptions). (Ledger R06.) — no later revision recorded; remains PROPOSED.
